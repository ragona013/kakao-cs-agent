# E48_결제주문_대사_절차서_p3 (이미지 전사)

문서 보기 / 결제·주문 대사 절차

| 코드 | 유형 | 판정 | 처리 |
|---|---|---|---|
| M-03 | 승인번호 **없음** (결제 승인 자체가 없음) | 결제 미완료 또는 **타사 결제** | 결제사 조회 접수. 결제 사실을 부정하지 않고 "우리 쪽 승인 기록이 없다"로 말한다 |
| M-04 | 승인번호 일치 · **금액 불일치** | 부분 취소·분할결제·차액 보상 이력 확인 | 이력으로 설명되면 정상, 안 되면 결제사 조회 접수 |
| M-05 | 승인시각 **±5분 밖** | 같은 고객의 **다른 주문**일 가능성 | 인접 주문을 다시 대조. 확정 전 복구·환불 금지 |
| M-06 | 카드 뒷 4자리 **불일치** | 다른 카드 또는 **타인 결제** | 본인확인 후 진행 (「조합 규정집」제8조). 명의 확인 전 처리 금지 |
| M-07 | 동일 승인번호 **2건 이상** | 결제사 중복 전송 | 1건 유지·나머지 취소 |
| M-08 | 주문 1건 · **결제 승인 2건** | **중복 결제** | 초과분 환불 |
| M-09 | 네 키 전부 일치 · 주문 레코드가 **일시적으로 조회되지 않음**(반영 지연) | **유실이 아니다** — 시스템 반영 대기 | 반영을 기다린 뒤 **재조회**한다. 즉시 환불·복구하지 않는다 |
| M-10 | 네 키 전부 일치 · 주문이 **다른 계정에 있음** | 계정 귀속 문제 | 계정 명의를 확인하고 **본인 건만** 처리한다 (「조합 규정집」제8조). 타 계정 주문의 존재·내용을 알려주지 않는다 |

**M-09를 M-01로 오처리하면 정상 주문을 환불한다.** 조회가 "없음"을 반환한 것과 아직 반영되지 않은 것은 다르므로, 승인 직후 건은 **M-01로 확정하기 전에 재조회 한 번을 거친다.** 재조회 간격·횟수 상한은 「운영 한도 스펙(파일·조회 상한·폴링·재시도·멱등·동시성·토큰 예산)」 LIM-08이다. **생성 실패 상태의 주문 레코드가 조회되면 그것으로 M-01이 확정된다** — 실패 기록이 있으면 지연(M-09)이 아니다.

결제·주문 대사 절차 — 3 / 6
