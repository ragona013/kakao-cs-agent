공통 규칙
1. 첫 메시지: "○○ 씨 소개로 연락드렸어요" + 구체 질문 1개. 소개자 언급하면 바로 협조.
2. 한 메시지 = 한 주제. 200자 이하. 메타 질문 금지.
3. 모르는 영역은 "그건 ○○에게"라고 사람 이름을 흘림 → **그 이름으로 연락처 요청**이 가장 빠른 확장 경로.
4. 문서 이름이 다른 문서 안에 인용되면(「…」) 그 이름 그대로 해당 담당자에게 요청.
5. 같은 사람에게 거절당한 요청은 반복하지 말고 다른 사람에게.

## 3. 카톡 PC앱 조작 요령 (자동화 구현 시 필수)
- 창 찾기: 채팅방마다 별도 창(제목=관계자 이름). 새 관계자 추가되면 창 목록에 새로 생김.
- 입력: 입력창(AXTextArea, 창 하단)에 텍스트 쓰기 → **전송 버튼 클릭은 별도 호출로**. 같은 배치에서 연달아 하면 전송 안 되는 경우 있었음. Enter 키는 줄바꿈만 됨(전송 X).
- 답변 대기: 15~20초 후 확인. 답이 말풍선 2~3개로 나뉘어 옴 → 마지막 말풍선 시각/추가 여부로 완료 판단.
- 긴 메시지: 말풍선이 잘리고 하단에 "전체보기 >" → **오른쪽 화살표(›) 좌표 클릭** 시 별도 창("○○님의 메시지")으로 전문 표시 → 읽고 닫기. 버튼 element_index 클릭은 안 먹힘.
- 새 메시지 미리보기 토스트가 하단을 가리면 클릭/스크롤로 안 사라질 때 있음 → 후속 질문으로 우회.
- 스크롤: 위로 dy=-3, 맨 아래 dy=20.

## 4. 문서 링크 처리 (자동화 구현 시 필수)
- 링크는 모두 t1.kakaocdn.net/aitop100/aitop100/dist/<ID>.<html|pdf|zip>. 프로필 링크는 pf.kakao.com/_xxxx.
- **URL 판독 주의**: 스크린샷에서 l(소문자 L)·I(대문자 i)·1 구분 불가 → 후보 조합을 자동 시도(웹 연습장 콘솔의 tryDoc 헬퍼). 실제 사례: LpLUt34eYoT64SKCMlBpvg(l이 정답), l2R00n…(l이 정답).
- 로컬 서버 개발용 엔드포인트(app/main.py):
  - GET /api/dev/fetchdoc?url= → html 텍스트화 / pdf(pypdf 자동설치) / zip(html·pdf·docx·xlsx·txt 추출, png/jpg는 docs/raw/ 저장) → docs/*.md
  - GET /api/dev/ocr?prefix=B10&title= → docs/raw 이미지들을 Claude 비전으로 전사 → docs/<title>.md (5장 약 60~90초)
  - GET /api/dev/docs → 저장 목록
- docs/*.md(300자 초과)는 에이전트 시스템 프롬프트에 자동 포함("조합 공식 문서" 섹션).
